# Convex Better Auth setup

## Current integration status

The Nuxt-to-Convex bridge, backend component registration, schema and HTTP
routes are implemented. A development deployment must still be selected per
developer through `pnpm exec convex dev`, because `.env.local` is intentionally
ignored.

Private deployment variables are never Nuxt variables:

```bash
openssl rand -base64 32 | pnpm exec convex env set BETTER_AUTH_SECRET
printf 'http://localhost:3000' | pnpm exec convex env set SITE_URL
```

This project has the component and its required peers installed:

- `@convex-dev/better-auth@0.12.5`
- `better-auth@1.6.25`
- `convex@1.42.3`
- `react@19.2.8` (peer required by the component package)

The command published by the component directory is:

```bash
npm install @convex-dev/better-auth
```

The equivalent command for this pnpm project is:

```bash
pnpm add @convex-dev/better-auth convex@latest better-auth@~1.6.25 react
```

## Exact setup checklist

### 1. Create or select the Convex development deployment

From the project root, run this interactively and keep it running during setup:

```bash
pnpm exec convex dev
```

This creates the `convex/` directory and generated types, and writes the selected
development deployment to `.env.local`.

### 2. Register the component

Create `convex/convex.config.ts`:

```ts
import betterAuth from '@convex-dev/better-auth/convex.config'
import { defineApp } from 'convex/server'

const app = defineApp()
app.use(betterAuth)

export default app
```

### 3. Configure the Convex authentication provider

Create `convex/auth.config.ts`:

```ts
import type { AuthConfig } from 'convex/server'
import { getAuthConfigProvider } from '@convex-dev/better-auth/auth-config'

export default {
  providers: [getAuthConfigProvider()],
} satisfies AuthConfig
```

### 4. Configure deployment secrets and URLs

The Nuxt development server uses port 3000:

```bash
pnpm exec convex env set BETTER_AUTH_SECRET="$(openssl rand -base64 32)"
pnpm exec convex env set SITE_URL http://localhost:3000
```

Do not commit the generated secret or `.env.local`.

### 5. Configure the local Nuxt environment

Keep `CONVEX_DEPLOYMENT` generated by the Convex CLI and expose only public URLs
through Nuxt's public prefix:

```dotenv
CONVEX_DEPLOYMENT=dev:adjective-animal-123
NUXT_PUBLIC_CONVEX_URL=https://adjective-animal-123.convex.cloud
NUXT_PUBLIC_CONVEX_SITE_URL=https://adjective-animal-123.convex.site
NUXT_PUBLIC_SITE_URL=http://localhost:3000
```

Add the matching public runtime configuration to `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      convexUrl: '',
      convexSiteUrl: '',
      siteUrl: '',
    },
  },
})
```

`CONVEX_SITE_URL` is supplied inside the Convex runtime. It is not a Nuxt
client variable and must not be copied into client code.

### 6. Create the Better Auth backend

After `pnpm exec convex dev` has generated `convex/_generated`, create
`convex/auth.ts`:

```ts
import type { GenericCtx } from '@convex-dev/better-auth'
import type { BetterAuthOptions } from 'better-auth/minimal'
import type { DataModel } from './_generated/dataModel'
import { createClient } from '@convex-dev/better-auth'
import { convex, crossDomain } from '@convex-dev/better-auth/plugins'
import { betterAuth } from 'better-auth/minimal'
import { components } from './_generated/api'
import { query } from './_generated/server'
import authConfig from './auth.config'

const siteUrl = process.env.SITE_URL!

export const authComponent = createClient<DataModel>(components.betterAuth)

export function createAuth(ctx: GenericCtx<DataModel>) {
  return betterAuth({
    baseURL: process.env.CONVEX_SITE_URL,
    trustedOrigins: [siteUrl],
    database: authComponent.adapter(ctx),
    emailAndPassword: {
      enabled: true,
      requireEmailVerification: false,
    },
    plugins: [
      crossDomain({ siteUrl }),
      convex({ authConfig }),
    ],
  } satisfies BetterAuthOptions)
}

export const getCurrentUser = query({
  args: {},
  handler: async ctx => authComponent.getAuthUser(ctx),
})
```

### 7. Mount the HTTP handlers

Create `convex/http.ts`:

```ts
import { httpRouter } from 'convex/server'
import { authComponent, createAuth } from './auth'

const http = httpRouter()

authComponent.registerRoutes(http, createAuth, { cors: true })

export default http
```

If the Convex bundle hits its memory limit, use `registerRoutesLazy()` as
recommended by the component's debugging guide.

### 8. Create the Vue Better Auth client

Create `app/lib/auth-client.ts`:

```ts
import { convexClient, crossDomainClient } from '@convex-dev/better-auth/client/plugins'
import { createAuthClient } from 'better-auth/vue'

export function createForusAuthClient(baseURL: string) {
  return createAuthClient({
    baseURL,
    plugins: [convexClient(), crossDomainClient()],
  })
}
```

### 9. Add the Nuxt-to-Convex client bridge

The installed component exposes `@convex-dev/better-auth/react`, but no
`@convex-dev/better-auth/vue` provider. Better Auth itself does expose
`better-auth/vue`.

Therefore, do not copy the React-only `ConvexBetterAuthProvider` example into
Nuxt. Before building login screens, add a client-only Nuxt plugin that:

1. creates the Better Auth Vue client with `NUXT_PUBLIC_CONVEX_SITE_URL`;
2. creates `ConvexClient` from `convex/browser` with
   `NUXT_PUBLIC_CONVEX_URL`;
3. calls `ConvexClient.setAuth()` with a token fetcher backed by
   `authClient.convex.token()`;
4. re-registers that fetcher whenever the Better Auth session ID changes;
5. handles the cross-domain one-time token (`ott`) after OAuth redirects;
6. closes the Convex client when the Nuxt app is disposed.

This bridge is the only framework-specific step not supplied as a ready-made
provider by `@convex-dev/better-auth@0.12.5`.

### 10. Configure optional providers

Email/password needs no additional provider variables. Each OAuth provider adds
its own client ID and client secret, for example:

```text
GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
GITHUB_CLIENT_ID
GITHUB_CLIENT_SECRET
```

Set provider secrets with `pnpm exec convex env set`; never expose them with
the `NUXT_PUBLIC_` prefix. Configure callbacks as:

```text
https://<deployment>.convex.site/api/auth/callback/<provider>
```

## Required environment variables

| Scope             | Variable                      | Required  | Purpose                         |
| ----------------- | ----------------------------- | --------- | ------------------------------- |
| Convex deployment | `BETTER_AUTH_SECRET`          | Yes       | Session encryption and hashing  |
| Convex deployment | `SITE_URL`                    | Yes       | Trusted application origin      |
| Convex runtime    | `CONVEX_SITE_URL`             | Automatic | Better Auth HTTP base URL       |
| Local CLI         | `CONVEX_DEPLOYMENT`           | Yes       | Selected development deployment |
| Nuxt public       | `NUXT_PUBLIC_CONVEX_URL`      | Yes       | Convex WebSocket/API URL        |
| Nuxt public       | `NUXT_PUBLIC_CONVEX_SITE_URL` | Yes       | Better Auth HTTP URL            |
| Nuxt public       | `NUXT_PUBLIC_SITE_URL`        | Yes       | Browser application origin      |
| Convex deployment | Provider client IDs/secrets   | Optional  | OAuth providers only            |

## Verification

### Static and build gates

```bash
pnpm install --frozen-lockfile
pnpm exec convex dev --once
pnpm lint
pnpm typecheck
pnpm build
```

### Authentication flow

1. Sign up with email/password through `authClient.signUp.email()`.
2. Sign out, then sign in through `authClient.signIn.email()`.
3. Confirm `getCurrentUser` returns the authenticated user.
4. Confirm a protected Convex query fails while signed out and succeeds while
   signed in.
5. Reload the browser and confirm the session persists.
6. Open a private page in a fresh tab and confirm there is no authenticated
   query before the token bridge is ready.
7. For each OAuth provider, verify the callback uses the `.convex.site` URL and
   that the `ott` parameter is consumed and removed from the browser URL.
8. Sign out and confirm cached authenticated queries are no longer accessible.

### Troubleshooting

Enable backend component logs temporarily:

```ts
export const authComponent = createClient(components.betterAuth, {
  verbose: true,
})
```

For bundle memory failures:

```bash
pnpm exec convex dev --once --debug-bundle-path /tmp/convex-bundle
```
